数据传输或存储, 总难免数据bit 反转或错误, 所以有纠错码算法. 
- 自动纠错: 重复码, 汉明码, RS 码, 卷积码, LDPC
- 检测不纠: 奇偶校验, CRC

简介:

- 重复码: 一个bit 重复 N 多次, 收端用占多数的作为解码结果
- 汉明码: 安排多个个校验位， 每个管住一部分数据位，让多个是非问题的答案拼起来正好是出错位的编号(只额外加 1 位校验bit，只能回答"有没有错"这一个是非问题，说不出错在哪)
- RS 码: 把数据当成一个多项式的系数,多发几个取值点;收端用任意足够多的点重建多项式 —— 因此擅长成片丢失(擦除/突发错误)
- 卷积码: 输出 bit 由当前输入和前几个输入滑动卷积而来,错误的影响被摊到后续多个输出上;收端用 Viterbi 在网格图上找最可能的路径
- LDPC: 用一个极稀疏的校验矩阵定义大量局部约束,收端在变量节点和校验节点间反复传递"这一位是 0/1 的置信度"直到收敛 —— 迭代到逼近香农极限

- 奇偶校验: 加额外一个bit, 说该组bits 的1总数是奇数还是偶数. 有一个bit 反转, 则检验不通过
- CRC:
  - encode: 把消息当成二进制多项式,除以一个约定的生成多项式,把余数附在后面
  - decode: 收端整体再除一次,余数非零即出错 —— 对突发错误检出率极高

----

## LDPC

以上各种, 多是处理的离散的 0/1数据. 只有 LDPC 不同 , 他的 decoder 可以接受每个 bit 是 0~1 float 的软信息, 并试图恢复出离散bits 流(毕竟, 物理实现上, 每个bit 都是用模拟信号来表达的). 正式在这样的灰度数字中, 把数据恢复了回来. 
- LDPC、卷积码、Turbo 码、Polar 码等很多纠错码，都可以使用 软判决输入，也就是接收端不仅告诉解码器“这个 bit 看起来是 0 还是 1”，还告诉它“有多像 0/1”

LDPC 也要增加额外校验bits, 作为整体传输的时候, 校验 bits 也是 float 的. 它比其他的方法: 同样多的检验bits, 支持从更多的错误中恢复. 同样的错误恢复率, 可以用更少的检验bits. (且距离香农极限很小)

解码是靠多次迭代解.

5G通信/Wi-Fi/SSD 都用到了他(深空航天器通信也用它).

### H 矩阵

H 矩阵是死的吗？ 是的，H 矩阵是提前设计好的，但不同场景用不同的 H 矩阵！ H 矩阵是什么, 举个简单例子（实际会大得多）：

```
     c1 c2 c3 c4 c5 c6   ← 每列对应一个 bit
r1 [  1  1  0  1  0  0 ] ← 第1个校验约束
r2 [  0  1  1  0  1  0 ] ← 第2个校验约束
r3 [  1  0  0  0  1  1 ] ← 第3个校验约束

行 = 校验方程数量
列 = 码字总 bit 数(=原始数据bits+校验bits)

每一行代表一个约束：
  r1: c1 ⊕ c2 ⊕ c4 = 0
  r2: c2 ⊕ c3 ⊕ c5 = 0
  r3: c1 ⊕ c5 ⊕ c6 = 0
```
 
矩阵是"低密度"(据大部分是0), 实际 LDPC 的 H 矩阵 几千行 × 几万列, 但每行只有 6~10 个 1, 密度 < 1%
  
### Tanner 图

Tanner 图就是 H 矩阵的图形化表示

```
H 矩阵：
     c1 c2 c3 c4 c5 c6
r1 [  1  1  0  1  0  0 ]
r2 [  0  1  1  0  1  0 ]
r3 [  1  0  0  0  1  1 ]
```

```
对应的 Tanner 图：

变量节点（每个 bit 一个）：
  c1    c2    c3    c4    c5    c6
  ○     ○     ○     ○     ○     ○
  │╲    │╲    │     │     │╲    │
  │ ╲   │ ╲   │     │     │ ╲   │
  │  ╲  │  ╲  │     │     │  ╲  │
  □    □              □
  r1   r2            r3

校验节点（每个约束方程一个）：
  r1    r2    r3
  □     □     □
```

如上, 校验 bit 就在 c1~c6 里面！r1, r2, r3 不是 bit，是约束方程(r1: 类似这样 c1 ⊕ c2 ⊕ c4 = 0)


解码:
- LDPC 解码, 就是解方程(在所有满足 Hcᵀ = 0 的合法码字里，找到和接收信号最匹配、概率最大的那个). 但是方程解不一定唯一. 所以实际系统都会在 LDPC 外面再套一层 CRC 来验证结果的正确性。
- 一个bit 即使是 0.95, 也可能被纠成 bit 0.
- 不是靠相邻关系决定当前bit 应该是0还是1, 而是靠约束
- 迭代译码：  就是在这张图上来回传消息, 直到所有约束都满足
