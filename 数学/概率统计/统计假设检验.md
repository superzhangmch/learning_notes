不只是平均值可以做假设检验, 其他比如中值, 也可以做. 可以是断定你拍定的 μ₀ 和 ground truth mean 是否相等, 其实也可以做是否大于(而非等于)的假设检验.

下面只看关于平均值的. 那么就是: ground truth 的均值你不知道, 只好有个自己的猜测, 拍定一个均值 μ₀, 然后是通过实际采样看是否背后的 ground truth 是否就是 μ₀.

这涉及到下面的分布:
- 原数据真实分布: 这个我们是不知道的. 我们不知道它的真正均值 μ.
- 采样分布: 被关注的统计量(比如均值)的采样分布. 假设一次采样时sample 100个, 那么这100个样本的均值服从什么概率分布? 这个分布就是采样分布. 它由两个东西决定: 一次采样的数量n, 以及你拍定的那个猜测 μ₀. 不同的 n与 μ₀ 对应不同的采样分布.
  * 原始数据分布你都不知道, 凭啥你能根据 n 和 μ₀ 断定精确的采样分布? 实际中, 都是取近似: 先假设采样分布服从某个分布, 而这个假设的采样分布本身有一定要求, 只要要求能满足, 则要么采样分布就是精确的, 要么是很好的近似. 比如对均值假设检验: 如果原始数据时正态分布, 则t分布就是精确的采样分布; 如果原始数据不是正态分布, 只要它还满足中心极限定理(比如柯西分布就不满足), 那么只要n比较大, 这时用t分布也是很好的近似.

有了采样分布（注意它的构造和当前的采样结果无关, 当前采样只是该分布的一个具体sample而已), 就可以算 p-value了: 当前这次n抽样，只是采样分布中一个点，于是可以算出分布密度图中比这个点（即本抽样的均值）更极端的整个区域的面积或概率，这就是 p-value。如果当前抽样处于采样分区图密度稀疏区，基于小概率实践不容易发生原则，判定要么是你的mu_0猜测不对，要么是猜测对但是小概率事件发生了。检验假设用的是前者：你猜错了。

注意：
- 需要先猜测后抽样做假设检验，如果拿采样到的n个的均值用来做，一定是相等的。没意义。
- n 太大也不好。n 越大越置信，但是现实中不可能100% 猜对μ₀，这样如果n太大导致再精准定位猜测都是不显著了：不支持猜测成立。

什么是置信区间呢：所有的使得当前采样按同一 p-val 阈值都显著的所有 μ₀ 构成的集合，就是置信区间。也就是说，置信区间是关于好多个采样分布而言的，而非基于当前采样分布。所幸这个置信区间中元素基本都是连成片的而非一个个孤立点。

----

用于实际

常用的几个场景：
- 一次采样n个，看均值是否和猜测一样。
- 对采样的 n 个点，两次对他们做测量，看前后是否有差异。（配对）
  * 直接每个点上求差, 看这个差集就行, 仿佛一开始采样了n个diff. 于是被检验的量是 μ₁ − μ₂, 看是否它是0
- 做两次测量，每次采样不同数量的样本点, 采样两次, 看两次是否有显著差异。（不配对）
  * 如果配对更好, 不配对也能搞, 不过达到同样的显著验证, 需要更多的样本点. (比如看一种糖尿病药物有效性: 看同一批人用药前后血糖值看药物效果只需要少量人; 如果不同的人, 那就是大量的人的用药前平均和用药后平均, 才容易看出效果差异)
- 时间序列配对: 按时间配对的两个时间序列集合，是否二者差异显著
  * 统计检验一般是要求抽样的 n 个数据之间两两独立, 而时间序列的时间依赖性往往打破了这一点. 所以要么不考虑这点, 否则是不能用常用的 t 分布等来处理的.
  * 关于互联网功能验证那种 ab-test: 往往呈现出的是时间序列配对形式, 每天有了一些数据, 所以每天可以对feature 有一个对比的指标, 跑了2周, 看看哪个好. 实际操作上, 其实并不考虑这个时间性. ab-test 的每个分支都是跨天固定了不同的用户, ...
