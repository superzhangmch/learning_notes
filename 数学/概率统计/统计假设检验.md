## 统计假设检验

- 要注重功效. test 之前: 要选定好显著性水平, 以及功效(从而需要选好最小作用效应Δ, 以及最小抽样数n). 这样看 p-val 才有效.
- 不只看 p-val, 还要看置信区间.
- 对于 CTR 等ab-test, 要多天数据全聚合后做.

假设检验一般是 H₀: 均值 = μ₀，也可以对其他统计量做检验，比如中位数。备择假设也可以是均值 ≠ μ₀、均值  > μ₀ 等。如果希望证明均值≈μ₀, 假设 H₀: 均值 ≠ μ₀，会转为 H₀: |均值 - μ₀| ≥ Δ 来处理(TOST 等价性检验)。

下面主要看关于均值的检验。ground truth 的均值未知，只好自己猜测，拍定一个均值 μ₀，然后通过实际采样来判断背后的 ground truth 均值是否就是 μ₀(本意其实反而是推翻这个 μ₀)。

这涉及到以下几个分布：
- 原始数据的真实分布：未知，其真正均值 μ 也未知。
- 采样分布：所关注的统计量（比如均值）的采样分布。假设一次采样取 100 个样本，这 100 个样本的均值(此乃统计量)服从什么概率分布？这就是采样分布。它由两个东西决定：单次采样的数量 n，以及拍定的猜测值 μ₀。不同的 n 与 μ₀ 对应不同的采样分布。
  * 原始数据分布都不知道，凭什么能根据 n 和 μ₀ 断定精确的采样分布？实际中都是取近似：先假设采样分布服从某个已知分布，而该分布本身有一定的适用条件，只要条件能满足，采样分布要么是精确的，要么是很好的近似。以均值的假设检验为例：如果原始数据服从正态分布，则 t 分布就是精确的采样分布；如果原始数据不是正态分布，但只要满足中心极限定理的条件（柯西分布就不满足），那么当 n 足够大时，单次抽样的均值就会很好地近似真实均值，此时用 t 分布也是很好的近似(所以中心极限定理这里是作用于单次抽样的n样本, 而不是多次采样)。

有了采样分布（注意它的构造与当前的采样结果无关，当前采样只是该分布的一个具体样本），就可以计算 p-value 了：当前这次 n 个样本的抽样结果，只是采样分布中的一个点，于是可以算出密度图中比这个点（即本次抽样的均值）更极端的区域的面积，这就是 p-value。如果当前抽样落在采样分布密度稀疏的区域，基于"小概率事件不容易发生"的原则，可以判定：要么是 μ₀ 的猜测不对，要么是猜测对了但小概率事件恰好发生了。假设检验采用前者：认为猜错了。这正是一种反证法的思想。

注意：
- 假设检验需要先猜测 μ₀，再抽样。如果用采样到的 n 个样本的均值来设定 μ₀，那么检验统计量一定等于 0，p-value 一定等于 1，毫无意义。
- n 也不是越大越好。n 越大，检验越灵敏，但现实中 μ₀ 不可能与真实均值完全一致，n 过大会导致哪怕极微小的偏差都呈现出"显著差异"——永远告诉你二者差异显著，反而拿不到真正关心的结论。
- n 个样本点要相互独立。
- 从上面内容可见：
  - p-value 不是 ground-truth 分布上的概率，也不是猜测的μ₀分布上的概率，而是采样分布上的概率；1 - p_value 也不代表"有显著差异"的概率。
  - H₀ 为真时，p-value 服从 [0, 1] 上的均匀分布：p-value 本质上是"当前抽样结果在采样分布中排在第几个百分位"，百分位天然均匀分布。这一性质被破坏的三种情形：参照分布选用错误、检验统计量是离散的、H₀ 本身就是假的。
- 上文一直说"猜测 μ₀"或"猜测 H₀"，但实际上你并非并非真心认为如此，而只是一种假设性的设定——真正的目的恰恰是否证它。比如新药效果的检验：H₀ 设定为"药物无效"，而研究者真正希望的是推翻这一假设。

### 置信区间:

什么是置信区间？所有使得当前采样结果按同一 p-value 阈值都不显著的 μ₀ 构成的集合，就是置信区间。也就是说，置信区间是针对许多个不同的采样分布而言的，而非基于某一个固定的采样分布。它完全由当前这次具体的 n 个样本决定，独立于你事先猜测的 μ₀——可以先算出置信区间，再看你的 μ₀ 是否被它覆盖。

95% 置信区间的正确含义是：如果反复抽样，有 95% 的抽样所构造的置信区间(每个采样有自己的置信区间)会覆盖住 ground-truth。那么也就意味着: "ground-truth 有 95% 的概率落在当前抽样的这个区间里"(在频率派框架下，ground-truth 是固定值，某次抽样构造出的区间也是固定的，没有随机性，所以不能赋予概率——按此说法引号中这句话是不对的. 而假设检验是频率派框架内的, 而非贝叶斯派的. 一次采样的置信区间是否95%概率覆盖ground-truth, 这个争辩这有些哲学味道了)

现实中，除了看 p-value，还要关注置信区间。

### 显著性α/置信区间/p-val 关系: 

显著性α/置信区间是同一个东西的两面. α 和 p 都是同一条采样分布的密度图上"某个切点以外的尾巴面积"，区别只在切点是谁定的。

```
横轴 = 统计量 t,  曲线 = H₀ 为真时它的密度 (对应μ₀)

                      ___
                    /     \
                  /         \
              __ /             \ __
          ────┬──────────┬───┬──────→  t
           −t_crit     t_obs  t_crit

  α    = t_crit 以外两侧尾巴的面积     ← 切点由 你 事先定
  p    = t_obs  以外两侧尾巴的面积     ← 切点由 数据 定
  1−α  = ±t_crit 之间的面积(接受域)

  判定 p < α   ⟺   t_obs 比 t_crit 更靠外
```

所以"显著"这件事，用面积说是 p < α，用位置说是观测值比临界值更靠外，完全是一回事。顺带一个推论：p 的切点是随机的（观测值每次都变），α 的切点是固定的，这就是为什么 p 是随机变量而 α 是常数。

图中这条密度的横轴是统计量；置信区间是一段参数 μ 的范围。两者是不同的轴。
- 显著性水平 α: 在密度上, 是尾巴的面积
- 置信水平 1−α: 在密度上, 是中间的面积
- 置信区间: 不在密度上, 是把中间那段反演到参数轴之外的 μ 的产物

最后，这个视角还顺手解释了"为什么 H₀ 为真时 p 值均匀"：因为 p 的切分点（观测值）本身就严格服从那条密度，而把一个连续随机变量代入它自己的分布函数，结果必然是 0 到 1 上的均匀分布。

### 功效 -  power/statistical power

|            | 真相：H₀ 为真 | 真相：H₀ 为假 |
|------------|---------------|---------------|
| 判定拒绝H₀(pVal < 0.05)   | α = 5% / 第一类错误 | 功效 / 正确 |
| 判定不拒绝H₀(pVal ≥ 0.05) | 1 − α = 95% / 正确 |  β = 1 − 功效 / 第二类错误 |
| 列和       | 1             | 1             |

(先说一句, 功效不是抽样后算出的, 是抽样前的设置; 是为了保证, H₀被推翻之后你的采样是能落入你更希望成立的 μ 的采样分布的非尾巴区域.)

看如上拆解: 检验假设的目的, 肯定是希望无论H₀是否被推翻, 一定要误差小, 也就是两类错误都要小. 
- 第一类错误: H₀ 为真, 你却拒绝了它, 错杀
- 第二类错误: H₀ 为假, 你却没拒绝它, 放过

正好被两个参数所控制: 
- α: 被硬性控制在比如 5%(或 1%), 是一条纪律. 它自动兑现, 你写下 0.05, 检验就按 0.05 执行, 不需要事前算样本量.
- β: 只是"希望不超过 20%"(即功效 ≥ 80%), 是一个目标. 一般设置为 power 为80%.
  * 它无法自动兑现: 需要由某些实验设置(比如采样数n等)来决定.

α, β 都是在抽样之前就要预先设置好的, 用来保证你接下来的抽样检验假设要做的有意义: 
- "H₀ 为真"绑定 μ₀，"H₀ 为假"绑定所有 μ ≠ μ₀，α 是一个数，β 是 μ 的函数。检验名义上猜 μ₀，实际想推翻它, 于是 α 保证置信地推翻它, β 保证推翻后抽样结果其实是会落在某个与μ₀有足够区分(足够Δ)的 μ_A 分布的高密度区(功效区). α 约束自动满足, 而 β 约束一般要求你有足够大的 n.
- 抽样之前，你先声明一个分辨力要求 μ_A（最小值得发现的效应），算出在那一点上功效要 ≥ 80%，由此定下样本量。
- 抽样之后，p 值负责判定推不推翻，置信区间负责回答"真正的 μ 大概在哪"。功效到这一步已经用完了，它保证的是"如果真有值得发现的效应，我不会漏掉"。

功效不是抽样后算出的, 是抽样前的设置; 为满足功效要求, 你需要提前设置好最小样本数 n 以及最小效应Δ, 设置好后的采样, 如果H₀被拒绝, 则设定的功效自动满足.

注意(上面图), 如果一次抽样落在了第一条曲线（μ₀ 采样分布）的左侧尾部，则 H₀ 被拒绝。但此时对于第二条曲线（μ_A 采样分布）来说，这次抽样同样落在了它的左尾，而非右侧的功效区——这并不是我们想要的结果，这就是 Type S 错误（Type Sign error，符号错误）：方向搞反了。所以除了看 p-value 是否显著，还需要关注效应的方向。方向不对，即使 p-value 再小，拒绝 H₀ 也没有意义——比如降压药的检验以 p=0.001 的显著性得出"血压显著升高"的结论，显著是显著，但完全不是你想要的。

功效低, 意味着什么, 容易导致什么:
- 按定义，第二类错误率 β = P(不拒绝 H₀ │ H₀ 为假) 会高。 这是定义直接给出的，因为功效 = 1 − β。图上就是第二条曲线落在临界线内侧那块（灰色区）变大。
- 你的满心欢喜可能是假的。 FDR = P(H₀ 真 │ 拒绝 H₀) 会高：p < 0.05 判了显著，看着支持药效，但药本身无效的可能性反而很大。所以功效不能低。
  * 注意：type-I error rate α = P(拒绝 H₀ │ H₀ 为真) 是预定义的 5%，它不会变。变高的是 FDR。
- 导致你不必要的沮丧。 FOR = P(H₀ 假 │ 不拒绝 H₀) 会高：p > 0.05 说药没效，其实有效，这种情况变多。"没效果"结论可能是错的。

总结: 
- 抽样前定下 α 和功效，本质上是在挑一个拒绝域：它在 H₀ 下罕见（概率 = α），在 H₁ 下——严格说在某个 μ = μ_A上——常见（概率 = 功效）。两者之比 功效/α 就是"拒绝"这件事的证据力；若两边都罕见，那么即便推翻了 H₀，也谈不上支持 H₁。"拒绝了 H₀"只是拿到了入场券，真正的判断在区间和阈值的相对位置上。按p-val极显著，但区间告诉你效应很小，那也毫无价值。
- 关于 H₁：它是 H₀ 的补集. H₀: μ = μ₀ → H₁: μ ≠ μ₀. 算功效时那个 μ_A, 是从 H₁ 那一整族里挑出来的一个代表点，用来画上图第二条曲线。它不是假设，是设计参数，和 α 一样是你填进去的。

**怎么设置功效: 怎么选择最小作用效应Δ, 以及最小抽样数n**

功效或者说 β, 与最小作用效应Δ, 以及最小抽样数 n 有关. 所谓test 之前要设置好功效, 其实就是选好 Δ 与 n.

test 设置需要满足:  Δ / SE(Δ̂)  ≥  z_α + z_β (Z_x 是正态分布的 x 分位值)
- Δ  = 你关心的效应(原始单位计量, 如 mmHg、米、毫秒、百分点), 或者说你的策略希望的提升(比如降压药, 能降多少 mmHg)
  - Δ = 0.002: CTR 从 4.0% 涨到 4.2%, 差 0.002 (也就是 0.2 个百分点)
  - Δ = 6.125: 血压降了 6.125 mmHg
- SE = 该效应估计量的 standard error(估计值本身的标准差)

上面的一般式, 往往可以化简为 d·√n ≥ z_α + z_β 形式(但不是一定)
- d = avg(..) / stdev(..), .. 是统计量, 比如配对test, 就是差值. 分母 stdev 项一般来自之前数据的统计, 而分子项, 则是提前拍定的: 比如你觉得你的你的降压新药很有用, 能降压多少, 那么这里就是作用效果指标.
- 从这个式子, 你的预期作用效果 d 有了后, 为了令式子满足, 至少需要多大的 n, 就可以算出来了. 然后就可以按这个采样量来抽样做test了.
  * d 越小, n 需要越大. 也就是要用假设检验方法衡量出这个小的d, 必须加大样本量.
  * 给定n, 反推出的 d, 可以看这个事情还搞不搞: 如果反推出的 d 太大, 而你的策略根本瞧不懂, 还怎么搞?

对: d·√n ≥ z_α + z_β

| 解哪个 | 公式              | 实例                                | 什么时候用               |
|--------|-------------------|-------------------------------------|--------------------------|
| n      | n = (z_α+z_β)²/d² | 想检出 5% 相对提升 → 每组 154,301   | 业务说得出"多大才值得做" |
| d      | d = (z_α+z_β)/√n  | 每组只有 150,000 → 最小能看出 5.07% | 流量限死，问灵敏度. 这叫求 MDE（最小可检测效应） |
| 功效   | Φ(d√n − z_α)      | d 和 n 都定了 → 算出 80%            | 事后复盘或方案比较       |
| α      | z_α = d√n − z_β   | 达不到就问"放宽到 α=0.10 行不行"    | 探索性研究，少用         |

**关于 α 与 β的权衡**

在给定的 n 下, 两类错误(α, β)难以都很小, 所以需要权衡. 一般是选择接受较小的 α(5%), 容忍稍微大点的 β(20%). 选择太小的 α, 等于自愿放弃功效.

α 该多小，取决于两种错误的**代价之比**，而不是"越小越好"：

| 假阳性(H0为真报为假/第一类错误)的代价 | 假阴性(H0为假报为真/第二类错误)的代价 | α 该怎么定 |
|---|---|---|
| 上线了没用的功能，浪费维护成本 | 错过了一个有效的改动 | 5%，惯例 |
| 批准了无效甚至有害的药 | 病人等更久 | 收紧，并要求确证性试验 |
| **筛选阶段**多捞几个候选，后面还会验证 | 漏掉真正的好候选 | **放宽到 10% 甚至更松** |
| A/B 的**护栏指标**：误报一次劣化，多查一次 | **没发现线上劣化，损失真金白银** | **放宽**，漏报代价更高 |
| 筛一万个基因 | 漏掉一个 | **大幅收紧**，Bonferroni 或 FDR |

注意第三、四行是**反方向**的：探索阶段和劣化监控，正确做法是**放宽** α，因为那时漏报更贵。

α 能定多小，取决于你有多少样本: 物理学宣布新粒子要 5σ，也就是 α ≈ 6e-7。他们敢这么严，是因为**对撞机能攒到天量数据**，δ 极大，所以即便临界值推到 5 个标准差，功效依然很高。而在上面那张表里，同样的 δ=2.8 下用 5σ，功效只剩 1.4%。同一个 α 在不同 n 下是完全不同的东西。

反过来算：要在 α=0.001 下仍保住 80% 功效，样本量得比 α=5% 多 118%。所以"更严的 α"是要花钱买的。

流程顺序: 

```
① α 按惯例或代价定死           5%, 不参与优化
② 功效目标按惯例定             80%
③ 解出需要多少 n               n = (z_α+z_β)²/d²
④ n 凑不够, 才回头调整:
     放宽 MDE (承认只能看出大改动)
     或上 CUPED 降噪
     或放宽功效到 70%
     ——注意这一步调的是 ③ 和功效, 极少去动 α
```

## 用于实际

常用的几个场景：
- 一次采样n个，看均值是否和猜测一样。
- 对采样的 n 个点，两次对他们做测量，看前后是否有差异。（配对）
- 做两次测量，每次采样不同数量的样本点, 采样两次, 看两次是否有显著差异。（不配对）
- 时间序列配对: 按时间配对的两个时间序列集合，是否二者差异显著

对以上:
- 配对对比: 直接每个点上求差, 看这个差集就行, 仿佛一开始采样了n个diff: 把 {x_i − y_i} 当成一列新采样到的数，检验它的均值是否为 0。
- 不配对对比: 如果配对会更好——为达到同样的显著验证, 不排队搞需要更多的样本点(比如看一种糖尿病药物有效性: 看同一批人用药前后血糖值看药物效果只需要少量人; 如果不同的人, 那就是大量的人的用药前平均和用药后平均, 才容易看出效果差异. 直观上就能感觉出)
- 时间序列的对比: 统计检验一般是要求抽样的 n 个数据之间两两独立, 而时间序列的时间依赖性往往打破了这一点. 所以其实是要先验证t依赖是否可忽略(比如看差值序列的 ACF，或跑 Ljung–Box等), 不可忽略时, 当配对检验, 就会有问题.
  * 关于互联网功能验证那种 ab-test: 往往呈现出的是时间序列配对形式, 每天有了一些数据, 所以每天可以对feature 有一个对比的指标, 跑了2周, 看看哪个好. 看起来就是这个时间序列配对看效果的场景. 实际中, 标准做法并不是这样处理的. 见下文.

另外, 对于配对类的, 如果不同样本本身均值都不太有意义或很不可信(但是因不同地区, 不同类别等, 其实还好; 配比的方法就把这种差异消除了), 或你其实关心的是谁好而不是差多少(关心P(X>Y)), 那么就应该用符号有关的检验等(Wilcoxon 符号秩 或 符号检验), 而不是t-test之类.

| 场景                     | 被检验的量 | H₀      | 主检验               | 稳健替代                     | 关键要点                                      |
|--------------------------|------------|---------|----------------------|------------------------------|-----------------------------------------------|
| ① 一组 n 个点 vs 猜测值  | μ          | μ = μ₀  | 单样本 t             | 符号检验                     | "单样本"数的是组数，一组里有 n 个观测         |

## 关于 ab-test

这里看互联网点击率 CTR 提升策略这类场景的 A/B test。一般做法是将用户群体分组，实验 n 天，每个用户的分组始终不变，通过统计曝光量和点击量，比较哪个分组的 CTR 更高。

人的直觉是急于看到效果，所以往往每天都去看当天的对比，以及所有天累计数据上的对比，并盯着每日走势图，希望新策略的曲线始终高于旧策略的曲线。

怎么衡量新旧策略的差异？

假设实验 10 天: 并不适合把数据整理成 10 个样本的配对数据来检验。这样做的问题是：无论用户量有多大，都被压缩成了 n=10 的检验，大量数据被白白浪费，本来显著的差异反而变得不显著。

正确的做法是将所有数据聚合后统一分析（相当于把 10 天的量合并成一份更大的数据；对单独某一天的数据也可以同样处理）。此时 n 是用户数，充分利用了数据，统计功效更高(功效低有啥危害, 看上文)，结果也更稳定。

聚合后 n 不是 1，而是总用户量。对数据按用户聚合: 
```
user_id   x(曝光)   y(点击)
u001         3         0
u002         1         1
u003        47         2
...

然后用: 总点击÷总曝光 + 按用户bootstrap:
① 每个用户一行两个数:  (他的曝光数, 他的点击数)
② 点估计:  两组各自 总点击÷总曝光, 相减
③ 不确定度: 有放回抓人抓几千次, 每次重算那个相减, 看结果散多开
④ 报告:   差异 ± 区间

以上具体细节没研究, 列出它, 只是唯了说明, 要多天聚合后仿佛一天来处理. 
```


对于 Google 这类大厂，可能几秒或一分钟的数据就能积累足够大的 n，并给出策略是否有显著差异的可靠检验结论。那么为什么不直接实验几分钟就下定论？原因在于：假设检验只能告诉你这几分钟内 A/B 两组是否有显著差异，但无法保证这几分钟的数据能代表真实的用户行为分布。至少需要完整的一天或一周，才能保证数据在时间维度上覆盖了各种场景；实验周期越长，样本的场景覆盖越充分，与真实分布的一致性越高。也就是说，延长实验时间，除了在流量较小时积累更多样本量之外，更重要的是保证样本的场景覆盖。此外还需要警惕新奇效应：新策略上线初期数据往往虚高，待用户适应后效果可能回落至真实稳态水平。
